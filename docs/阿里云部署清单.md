# 阿里云部署 qq-bridge + SnowLuma 操作清单

> 目标：把 QQ 侧（QQ 桌面版 + SnowLuma）放到阿里云 Windows 服务器上常开，
> 让平板上的 qq-bridge / DSH 能收发 QQ 消息。
> 前提：本清单由你亲手执行（账号、实名、付费、SnowLuma 条款确认都需要你本人）。

---

## 第 0 步：先验证，再花钱（重要）

云服务器**机房 IP 登录 QQ 风控很严**，扫码后可能触发设备锁、短信验证甚至冻结。
所以先按量付费开一天，只验证两件事：

1. QQ 桌面版能否在云 Windows 上扫码登录成功；
2. SnowLuma 能否成功注入（挂进 QQ 进程）。

**两件都过再考虑包月常开；任何一件失败就立刻止损、释放实例。**

建议用**小号 QQ** 测试，不要拿主号冒险。

---

## 第 1 步：开通阿里云 Windows 服务器

- 产品：**轻量应用服务器**（比 ECS 简单，自带 Windows 镜像）或已有 ECS 重装为 Windows
- 镜像：**Windows Server 2022 数据中心版**（64 位）
- 配置：**2 核 4G** 起（QQ + SnowLuma 常驻；2G 内存会紧张），系统盘 60G+
- 带宽：**5 Mbps 起**（远程桌面才不卡；按流量更便宜但注意 RDP 流量）
- 计费：**按量付费**（验证阶段），用完释放实例
- 安全组：先只放行 **3389（远程桌面）**，来源尽量填你家公网 IP

> 轻量应用服务器 Windows 镜像可能另收授权费，下单页面会显示，注意看。

## 第 2 步：远程桌面连上去

- 在阿里云控制台 **重置实例密码**（Administrator 用户）
- 平板上装远程桌面客户端：
  - 设备自带的 `com.xiaomi.mslgrdp` 可能是小米远程桌面，先试它；
  - 不行就装 **Microsoft Remote Desktop** 的安卓版（我可以帮你下载安装）
- 地址填云服务器**公网 IP**，端口 3389，用户 `Administrator`

## 第 3 步：Windows 基础设置（管理员 PowerShell）

```powershell
# 禁止睡眠/休眠（服务器关机就全断）
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0

# 远程桌面断开后保持会话（不注销程序）
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fResetBroken /t REG_DWORD /d 0 /f
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" /v MaxDisconnectionTime /t REG_DWORD /d 0 /f

# 关闭 IE 增强安全配置（下载安装包会用）
Set-ItemProperty "HKLM:\SOFTWARE\Microsoft\Active Setup\Installed Components\{A509B1A7-37EF-3D9B-4CF1-00CEF1276764}" -Name IsInstalled -Value 0
```

装 **VC++ 2015–2022 运行库（x64）**：<https://aka.ms/vs/17/release/vc_redist.x64.exe>

## 第 4 步：安装并登录 QQ（Windows 桌面版）

- 下载：<https://im.qq.com/pcqq> → 选 Windows 版
- 安装后登录：用手机 QQ「扫一扫」扫屏幕上的二维码
- 登录成功后**保持 QQ 运行**（可以设置开机自启）

> 风控提示：若提示「当前设备环境异常」「需要短信验证」「账号被临时冻结」，
> 说明机房 IP 被风控命中，这条路线基本走不通，直接止损。

## 第 5 步：安装 SnowLuma

- 下载：[SnowLuma Releases](https://github.com/SnowLuma/SnowLuma/releases) 里的
  `SnowLuma-v<版本>-win-x64.zip`（**完整版自带 Node 运行时**，Lite 版需要你另装 Node 22.13+）
- 解压到 `C:\SnowLuma`，双击 `launcher.bat`
- 首次引导（WebUI，启动日志里会打印地址，默认 `http://localhost:5099`）：
  1. 用启动日志里的初始密码登录 → 自己确认条款
  2. 设置密码
  3. 接入 QQ 进程（会自动检测你已登录的 QQ）
- 在 WebUI 里配置 OneBot：
  - 开启 **WebSocket 服务端**（默认 3001）
  - 开启 **HTTP API**（默认 3000）
  - 设置一个**长随机 accessToken** 并记下来
  - 若 WebUI 里能选监听地址，优先保持 `127.0.0.1`，下一步用隧道/端口转发访问

> ⚠️ SnowLuma 的 EULA 明确规定条款确认和安装由使用者本人完成，这一步我没有替你执行。

## 第 6 步：把云上的 OneBot 暴露给平板（二选一）

### 方案 A（推荐）：Tailscale 组网，不暴露公网端口

1. 云 Windows 装 [Tailscale](https://tailscale.com/download/windows) 并登录你的账号
2. 平板装 Tailscale 安卓版（我可以帮你装）并登录**同一账号**
3. 平板记下云服务器的 Tailscale 内网 IP（`100.x.x.x`）
4. 平板桥接连 `ws://100.x.x.x:3001` / `http://100.x.x.x:3000` —— 全程加密，不占公网端口

### 方案 B：公网直连（有暴露风险）

云服务器上管理员 PowerShell：

```powershell
# 用 Windows 自带端口转发，把公网端口转到本机 127.0.0.1
netsh interface portproxy add v4tov4 listenport=3000 listenaddress=0.0.0.0 connectport=3000 connectaddress=127.0.0.1
netsh interface portproxy add v4tov4 listenport=3001 listenaddress=0.0.0.0 connectport=3001 connectaddress=127.0.0.1

# Windows 防火墙放行
netsh advfirewall firewall add rule name="OneBot-3000" dir=in action=allow protocol=TCP localport=3000
netsh advfirewall firewall add rule name="OneBot-3001" dir=in action=allow protocol=TCP localport=3001
```

- 阿里云安全组放行 TCP 3000/3001，**来源尽量填你家公网 IP**（不确定就临时 0.0.0.0/0 + 长 token，用完收紧）
- 注意：明文 `ws://` 会把 accessToken 放在 HTTP 头里走公网，别在不可信网络长期用

## 第 7 步：改平板上的桥接配置

编辑 `$HOME/qq-bridge/config.json`（平板本地路径
`/data/user/0/app.dsh.mobile/files/dsh-home/qq-bridge/config.json`）：

```json
{
  "snowluma": {
    "wsUrl": "ws://100.x.x.x:3001",
    "httpUrl": "http://100.x.x.x:3000",
    "accessToken": "你在 SnowLuma 里设的长随机 token",
    "followDiscoveredEndpoint": false
  },
  "ownerQQ": 你的QQ号,
  "allow": { "private": [你的QQ号], "groups": [] }
}
```

- `followDiscoveredEndpoint` 必须改成 `false`（否则桥接会去 Windows 上找端口把地址改回本机）
- `allowAllWhenEmpty` 保持 `false`，白名单先只填自己
- 启动：`cd ~/qq-bridge && npm start`，日志出现 `SnowLuma 已连接` 即成功
- 然后在 QQ 上给机器人账号发条消息测试

## 第 8 步（备选）：整套都放云上

如果平板桥接连不通（网络策略/路由器拦截），可以把 DSH + 桥接也搬到云 Windows：

1. 云 Windows 装 Node 22.13+（或直接用 SnowLuma 完整版自带的 Node）
2. 放 qq-bridge 仓库 → `npm install` → 复制 `config.example.json` 为 `config.json`
3. 装 DSH（按官方文档在 Windows 上装 CLI/Web 版），把模型凭据配好
4. `node scripts/setup-dsh.mjs` 装 preset + MCP，重启 DSH
5. 平板改用浏览器访问云上的 DSH WebUI

> 这条路要重新配置一遍 DSH 环境，平板现有会话数据不会自动同步，成本更高，作为兜底。

## 成本与风险

| 项目 | 说明 |
|---|---|
| 实例费用 | 按量付费试一天约几元～十几元；包月常开约 80～150 元/月（配置/活动不同） |
| 流量 | RDP + 图片收发，按流量计费的话注意控制 |
| **封号风险** | **最大硬伤**：机房 IP + 新设备登录，QQ 风控命中概率远高于家用宽带；建议小号 |
| 合规 | QQ 用户协议禁止非官方客户端/机器人；SnowLuma 为第三方注入方案，风险自担 |
| 稳定性 | 云 Windows 无 GPU，QQ 界面偏卡但可用；QQ 大版本升级可能导致 SnowLuma 注入失效 |

## 验证顺序（止损点）

1. QQ 在云上扫码登录成功？
2. SnowLuma 注入成功（WebUI 显示 QQ 在线）？
3. 平板桥接日志出现 `SnowLuma 已连接`？
4. QQ 给机器人发消息 → 平板 DSH 里出现会话 → 回复能发回 QQ

任一步失败就停，不要继续付费包月。
