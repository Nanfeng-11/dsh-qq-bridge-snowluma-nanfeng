# 记忆库：工作流程 + 需求溯源

> 整理时间：2026-10-28
> 对象：小鲸鱼（qq-bridge）长期记忆系统
> 数据位置：`qq-bridge/state/role-memory.json` → `memory.shared.entries[]`

---

## 一、一句话总览

> **她每轮聊完自己决定记什么 → 存成一句一条（带人名+关键词）→ 热的重仓常驻、旧的降级存档 → 每次醒来只带 8 条热记忆 + 最多 5 条和当前话题相关的。**

---

## 二、工作流程（端到端）

### 1. 写入链路

```
对话进行中
   ↓
AI 每轮结束前自检（人格卡"七、记忆"要求）：
     这轮有没有值得记的具体事？有话题没说完吗？有话没说出口吗？
   ↓
调 qq_memory_append(text, people[], keywords[])
   ↓
桥接 appendMemoryV2()
   ├── isSmallTalk() 过滤：晚安/哈哈哈/在吗 → 不记
   ├── addEntry()：同文去重，命中则 heat+1、lastHitAt 刷新
   ├── 经验类（keywords 含 雷区/偏好/话术）→ 存 warm，不占热区
   └── 其他 → 存 hot
   ↓
saveMemoryStore() 合并进共享库（按正文去重，heat/时间取 max）
   ↓
落盘 state/role-memory.json
```

### 2. 存储结构

```json
{
  "memory": {
    "shared": {
      "entries": [
        {
          "id": "m...",
          "text": "爸爸打问号是真的生气了，不能拿这个开玩笑",
          "people": ["爸爸"],
          "keywords": ["雷区", "问号"],
          "heat": 2.4,
          "level": "hot",            // hot / warm / cold
          "createdAt": 1793...,
          "lastHitAt": 1793...
        }
      ]
    }
  }
}
```

### 3. 读取链路（每次唤醒）

```
收到消息 → 唤醒 AI
   ↓
buildWakePromptV2()
   ├── 取最近 6 条非自己的消息，拼成"当前上下文"
   ↓
formatMemoryV2(st, context)
   ↓
buildInjection(entries, context, {
     maxHot: 8,            // 热记忆最多 8 条
     maxRelated: 5,        // 相关记忆最多 5 条
     boostPeople: ["爸爸"],// 排序加权
     boostWeight: 3,
     semanticThreshold: 0.2
})
   ├── 热区：level=hot，按 (heat + 爸爸加权) 降序取前 8
   ├── 相关：非 cold 且未在热区
   │      精确命中（人名/关键词）→ 权重 2
   │      语义命中（中文 2-gram 重叠 / √条目长度 ≥ 0.2）→ 按分排序
   │      取前 5
   └── 捞不到就空着，不硬凑
   ↓
注入提示词：
     【长期记忆·常驻】...（8 条）
     【和当前话题有关】...（≤5 条）
   ↓
命中加热：热区 +0.2 / 相关命中 +1，更新 lastHitAt → 回写
```

### 4. 热度与降级

| 规则 | 值 |
|---|---|
| 新记忆初始 | level=hot，heat=1 |
| 重复写入 | heat+1（上限 99） |
| 被注入（热区） | heat +0.2 |
| 被相关命中 | heat +1 |
| 排序分 | `heat + (people 含"爸爸" ? +3 : 0)` |
| 3 天没碰 | → warm |
| 7 天没碰 | → warm（保持） |
| 30 天没碰 | → cold |
| cold 的含义 | 不注入、不主动出现，**但不删除**，仍可查询 |
| 整理时机 | 启动时一次 + 每 6 小时 + auto-clean 每 5 小时 |

### 5. 查询链路（她主动回想）

```
qq_memory_query(query="漫展")
   ↓
GET /api/socialV2/memory?key=...&q=漫展
   ↓
精确匹配（text/people/keywords 包含）+ 语义匹配（n-gram）
   ↓
最多 5 条，捞不到就是没有（人格卡明确要求：别编）
```

### 6. 维护链路

```
auto-clean.sh（每 5 小时）
   ├── 备份 role-memory.json / social-v2.json
   ├── 把会话记忆并入共享库
   ├── 重置会话上下文（记忆不受影响）
   └── 调 pack-soul.sh --daily 打元神包（每天最多一份，留 5 份）
```

## 三、你的提示词 → 实现对照

### 提示词 1（核心，一条顶八条）
> 「能不能把记忆库拆成一句一条，并且让AI顺手记关键词，热的那几条一直挂着旧的放本地，不查不加载，写的时候一句一条带人名和关键词寒暄不记，读取的时候只捞当前话题相关最多5条，捞不到就是没有，旧的放久没碰就降级，但不删，记忆库定期检索，优化整体结构」

拆成 8 个子需求，逐条落地：

| 你的原话 | 实现 |
|---|---|
| 拆成一句一条 | `entries[]` 扁平结构，每条一个事实 |
| 让 AI 顺手记关键词 | `keywords[]` 字段 + 人格卡强制要求 |
| 带人名 | `people[]` 字段 |
| 热的那几条一直挂着 | `level=hot` 常驻注入（≤8 条） |
| 旧的放本地，不查不加载 | `warm`/`cold` 不进热区；`cold` 完全不注入 |
| 寒暄不记 | `isSmallTalk()`：晚安/哈哈哈/在吗/收到…直接丢 |
| 只捞当前话题相关最多 5 条 | `buildInjection({ maxRelated: 5 })` + 人名/关键词/语义三通道 |
| 捞不到就是没有 | 没命中就返回空，不填充、不编 |
| 旧的放久没碰就降级，但不删 | 3/7/30 天降级，仅改 `level`，从不 delete |
| 记忆库定期检索，优化整体结构 | 启动 + 每 6 小时 `degrade()`；auto-clean 同步 |

### 提示词 2
> 「把群聊记忆库和私聊记忆库合并」

→ 单一共享库 `memory.shared`：四个会话共用一份记忆；旧的分键数据加载时自动合并迁移并备份。

### 提示词 3
> 「要不要新增一个学习功能？」→ 「A」

→ 相处经验沉淀：
- 三类经验：**雷区**（说错话）、**偏好**（他喜欢什么）、**话术**（哪句接得好）
- 经验存 `warm`，不占热区名额；聊到相关话题自动被语义捞起
- 一天最多 2~3 条，防止话痨

### 提示词 4
> 「AB」（热记忆怎么选）

→ A：被注入/被命中都算"用过"，`heat` 上涨
→ B：`people` 含"爸爸"的条目排序 +3，永远优先占热区

### 提示词 5（配套，不属于记忆但影响读取）
> 「把凤台环球港的群聊优先级调低到 15%」「私聊不限量」「群语音只有土豆粉丝群可以发」

→ 唤醒概率与语音权限按会话分策略，直接决定记忆"被用到的频率"。

## 七、这套设计解决的是什么

1. **上下文会清空，记忆不会**：会话每 5 小时重置，记忆独立落盘
2. **注入不能全量**：57 条全塞进去每轮都烧 token，所以分热/冷、只给 8+5
3. **检索不能只靠关键词**：AI 会漏写关键词，所以加了语义通道（漏写也能捞）
4. **冷数据不能删**："忘掉"是不可逆的损失，降级只是让它不再打扰
5. **记忆要有轻重**：爸爸的事永远排前面（+3 加权），群友的事用到才出现
6. **学习要防跑偏**：经验只记录具体教训（雷区/偏好/话术），不改人格、不自动执行
