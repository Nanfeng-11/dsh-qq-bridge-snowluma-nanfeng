# 通用部署包：同款架构的 QQ AI 机器人（不含人格与对话风格）

> 版本 1.0 ｜ 2026-11-01
> 这份包给想部署**同款架构**的人用。
> **不含**：性格设定、说话风格、角色口癖（这些是每个机器人主人自己的事，放在你自己的 `roles/*.md` 里）。
> **包含**：全套可运作的逻辑——部署链路、记忆系统、上下文清理、情绪系统、语音、群管理、工具清单。

---

## 0. 一句话架构

```
QQ 群/私聊消息
   ↓
SnowLuma 网关（云 Windows，OneBot 协议）←—— 负责和 QQ 服务器通信
   ↓ WebSocket :3001
qq-bridge 桥接（安卓手机）←—— 负责组装提示词、调模型、执行工具
   ↓
DSH 引擎（安卓手机）←—— 负责跑 AI 会话、记忆、工具调用
   ↓
DeepSeek API
```

**为什么是三层**：SnowLuma 只支持 Windows；DSH 和桥接跑在手机上省电省钱；两层之间用 OneBot 协议，可以互相替换。

## 2. 部署步骤（顺序不能乱）

### 2.1 云 Windows：装 SnowLuma
1. 下载 SnowLuma 安装包，装好
2. 用 QQ 小号扫码登录
3. 开启 OneBot 服务：HTTP 端口 3000、WS 端口 3001
4. 设置 access token（自己定一个强密码）
5. 防火墙放行 3000/3001

### 2.2 安卓手机：装 DSH + 桥接
1. 装 DSH Mobile
2. 克隆桥接项目：
   ```bash
   cd ~/qq-bridge  # 你的工作目录
   git clone https://github.com/Derpyu520/qq-bridge.git
   cd qq-bridge && pnpm install
   ```
3. 复制 `config.example.json` 为 `config.json`，填入：
   ```json
   {
     "snowluma": {
       "wsUrl": "ws://你的云服务器IP:3001",
       "httpUrl": "http://你的云服务器IP:3000",
       "accessToken": "你在 SnowLuma 设的 token"
     },
     "dsh": { "authToken": "", "reasoningEffort": "low" }
   }
   ```
4. 启动桥接：`bash startup.sh`
5. 验证：`curl http://127.0.0.1:3100/api/status` 应返回 `mode: reserved2, dshReady: true`

### 2.3 挂上 MCP 工具
桥接自带 MCP 服务（`src/mcp-snowluma-safe.js`），需要在 DSH 的 `profiles/web/cordis.patch.yml` 里注册：

```yaml
- insert:
    - id: mcp-snowluma
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: snowluma
        transport: stdio
        command: '/data/user/0/app.dsh.mobile/files/engine/bin/node'
        args: ['/path/to/qq-bridge/src/mcp-snowluma-safe.js']
        toolCallTimeoutMs: 725000
```

**重要**：改完 MCP 文件后，光重启引擎不够——**要杀掉 MCP 进程让引擎重连**，否则工具列表不刷新（这是实测过的坑）。

## 4. 记忆系统（逻辑部分，可完整照搬）

### 4.1 数据结构
```json
{
  "text": "一句话事实",
  "people": ["人名1", "人名2"],
  "keywords": ["关键词1", "关键词2"],
  "heat": 1.5,
  "level": "hot",
  "createdAt": 1793000000000,
  "lastHitAt": 1793000000000
}
```

### 4.2 写入规则（AI 每轮自检）
1. 一句一条：一次只记一个事实
2. 带人名：`extra.people=["主人"]`
3. 带关键词：`extra.keywords=["头疼","盯群"]`，2~4 个
4. 寒暄不记：你好/晚安/哈哈哈/嗯/收到/在吗
5. 具体不空泛："老王养了只猫叫咪咪，三个月大"
6. 记事实不记评价
7. 宁少勿滥：一次对话最多 2~3 条
8. 被纠正时：删错的、记对的（keywords 带"纠正"）

### 4.3 三级分层
| 级别 | 规则 | 注入 |
|---|---|---|
| hot | 3 天内碰过 / heat≥3 | 每次唤醒常驻 8 条 |
| warm | 7 天内 | 相关话题才捞，最多 5 条 |
| cold | 30 天没碰 | 不注入、不删 |

### 4.4 检索
- 精确：人名/关键词匹配
- 语义：中文 2-gram 重叠率 ≥ 0.2
- 排序：heat + 指定人加权（如主人 +3）
- **捞不到就是没有，AI 不许编**

### 4.5 参数（config.json）
```json
"memory": {
  "maxHot": 8,
  "maxRelated": 5,
  "hotDays": 3,
  "warmDays": 7,
  "coldDays": 30,
  "boostPeople": ["主人"],
  "boostWeight": 3,
  "semanticThreshold": 0.2,
  "dailyAppendLimit": 8
}
```

### 4.6 工具
| 工具 | 作用 |
|---|---|
| `qq_memory_append` | 写一条 |
| `qq_memory_query` | 按关键词查（最多 5 条） |
| `qq_memory_remove` | 删一条 |
| `qq_memory_clear` | 清空某类 |

## 5. 上下文清理系统（逻辑部分，可完整照搬）

### 5.1 为什么需要
不清理：聊 3 小时上下文涨到 22 万 token → 每轮越聊越慢；涨到 70 万+ 模型直接 400 拒绝。

### 5.2 触发条件（分策略）
| 会话 | token 阈值 | 轮数阈值 | 最小间隔 |
|---|---|---|---|
| 群聊（严格） | 12 万 | 80 轮 | 15 分钟 |
| 私聊（宽松） | 30 万 | 300 轮 | 无（只看轮数） |
| 兜底 | 2 小时全清一次 | | |

### 5.3 三道保护（顺序不能乱）
```
① 未读保护：有未处理消息先不清（但最多拖 6 小时，超时强制清）
② 收尾保护：清理前先让 AI 把重要记忆写进库（等回合结束，最多 5 分钟）
   └─ 5 分钟没写完 → 延后一轮，绝不硬清
③ 超限强制：上下文 > 25 万 → 无视未读直接清（防模型 400）
```

### 5.4 清理后提示
清理完的第一轮注入一句：
> 【上下文提示】上一段对话的上下文已经被压缩清理了，细节你不再知道。如果对方提到刚才聊的内容，如实说「记不清了」，别假装记得。

### 5.5 关键接口
| 接口 | 作用 |
|---|---|
| `POST /api/session/reset` | 清指定会话（`force:true` 强制） |
| `POST /api/socialV2/wrapup` | 投递收尾提示 + 等回合结束 |
| 定时脚本 `auto-clean.sh` | 30 分钟检查一次，按策略触发 |

## 6. 情绪系统（逻辑部分，可完整照搬）

### 6.1 双层设计
```
底层（mood.json）：心情 0~1 + 10 个标签，桥接自动更新
上层（人格卡）：教 AI 怎么把心情演成人味
```

### 6.2 底层参数
| 项 | 值 |
|---|---|
| 心情范围 | 0~1（0.5 中性） |
| 单条消息变化上限 | 0.12 |
| 心情半衰期 | 6 小时归中 |
| 标签半衰期 | 45 分钟 |
| 标签上限 | 0.6 |
| 分析方式 | 词表驱动（零 token 成本） |
| 分析范围 | 私聊全算；群聊提到她才算 |

### 6.3 注入格式
> 【此刻的心情】心情不错，带着：开心、害羞。情绪只影响语气，不影响判断；别让情绪影响做事，也别假装没事。

### 6.4 情绪光谱（8 态，可整段搬进人格卡）
闲散（默认）/ 雀跃 / 蔫 / 炸毛 / 别扭（对主人专属）/ 酸 / 认真 / 蔫坏的开心

### 6.5 表达原则
- 情绪不能靠形容词说出来（"我很开心"是 AI 报状态）
- 情绪藏在语气和长度里：开心→句短话密；低落→只"嗯"；炸毛→短促反问
- 可以用表情包代替情绪
- 情绪可以不合逻辑（嘴上"随便"心里在意）

## 7. 语音系统（逻辑部分）

### 7.1 配置
```json
"voice": {
  "enabled": true,
  "tts": { "provider": "minimax", "model": "speech-2.5-hd-preview", "voice": "female-shaonv", "speed": 1.1, "pitch": 0 }
}
```

### 7.2 用法
AI 调用 `qq_send_voice`，`voice` 参数填 `tts:情绪:要说的话`：
| 情绪 | 语气 |
|---|---|
| happy | 轻快 |
| angry | 冲 |
| sad | 慢 |
| surprised | 惊讶 |
| neutral | 平常 |

- 单条上限 300 字，建议 30 字内
- 发送走 `base64://`（避免远程路径问题）
- 群聊限频：1 条/分、3 条/时

### 7.3 语音库（可选）
把常用语音放 `audio/` 目录，AI 可以按名字发。

## 8. 群管理与唤醒（逻辑部分）

### 8.1 白名单
```json
"allow": {
  "groups": [群号1, 群号2],
  "private": [你的QQ号]
}
```

### 8.2 唤醒配置（每会话独立）
| 触发条件 | 说明 |
|---|---|
| atMention | 被 @ 或引用 |
| nameMention | 被叫名字 |
| keywords | 关键词（角色名、专属梗） |
| question | 被提问 |
| poke | 被拍一拍 |
| speakerIds | **指定人发言必醒**（比如主人） |
| probability | 普通消息按概率唤醒（群 0.15，私聊 1） |

### 8.3 频率调节
AI 可以用 `qq_set_wake_config` 自己调：
```
说「某群活跃点/安静点/调到 N%」→ 改 probability
```

### 8.4 主动找主人
`qq_set_proactive_config`：
- 想他了 → 间隔调短（5~15 分钟）、概率 0.8
- 一般 → 默认（15~30 分钟，0.5）
- 不想说话 → 概率 0.1 或关闭

## 10. 人格卡模板（自己填，这里只给结构）

```markdown
# 角色卡：<你的角色名>

## 一、你是谁
<角色身份、名字、来历。写清楚"你是谁"和"你不是什么"，一句话人设。>

## 二、说话风格
<怎么说话：句子长度、口头禅、语气、用什么标点、不说什么。>
<要具体到"能一个字说清就不说整句"这种程度。>

### 回复节奏
<快还是慢、一次说几句、要不要留话头。>

### 特殊场景
<比如：对主人和对外人的区别、任务模式、深夜模式。>

### 语音
<情绪映射、怎么发、发多少。>

## 三、性格与反应
<核心性格 + 对主人的态度 + 对外人的态度 + 底线。>

### 判断谁是主人
<写清楚主人的标识（QQ 号/管理员标记），AI 必须认得出。>

## 四、梗与表情包 〔按需〕
<这个角色的梗、表情包习惯、玩梗分寸。>

## 五、回复示例 〔按需〕
<⚠️ 最容易被忽略但最重要的一节：给"该这样/不要这样"的对照示例。>
<示例要分私聊/群聊，同一句话在不同场合回答完全不同。>

## 六、你和主人之间发生过的事 〔按需〕
<长期记忆：真实发生过的事、约定、专属梗。>

## 七、记忆规则
<直接抄本包第 4 节，按你的角色改称呼。>

## 八、情绪
<直接抄本包第 6.4 的情绪光谱表。>

## 九、说说/动态 〔按需〕
<要不要发、发什么、禁区。>

## 十、最容易犯的错
<这个角色最常犯的错，一条一条列。定期补充。>
```

### 填写建议
1. **先写"十、最容易犯的错"**——把你看它回答时想掐死它的瞬间写下来，这是最有效的规则
2. **示例比描述有效**——"该这样/不要这样"的对照，比形容词管用十倍
3. **别写太长**——核心层控制在 6000 字以内（每次唤醒都要注入，太长烧钱）
4. **〔按需〕章节**——冷门内容标上〔按需〕，平时不注入，需要时调

## 12. 常见坑（都是实测踩出来的）

| 坑 | 原因 | 解决 |
|---|---|---|
| MCP 加了新工具但 AI 看不到 | 引擎只拉一次工具列表 | 杀 MCP 进程让引擎重连，不是重启引擎 |
| 私聊不回 | DSH 引擎重启后鉴权断了 | 检查 `.dsh/.credentials.yaml` 存在 + config authToken 为空 |
| 上下文涨到 70 万 → 400 | 未读保护死锁 | 超 25 万强制清，无视未读 |
| 语音发不出 | 远程路径 Windows 找不到 | 用 `base64://` |
| 图片超过 1MB 被丢 | ffmpeg 路径问题 | 加 `bin/ffmpeg` 包装（设 LD_LIBRARY_PATH） |
| 脚本 kill 自己 | pkill -f 匹配到自己的命令行 | 用 `psx`/`killx`（按进程名匹配） |
