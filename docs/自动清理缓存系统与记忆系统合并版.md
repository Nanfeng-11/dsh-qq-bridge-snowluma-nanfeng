# 第一部分：自动清除缓存系统资料

## 1. 为什么需要自动清理

DSH 会话的上下文是**累积**的：每轮对话都把「人格卡 + 记忆 + 历史消息 + 工具结果」重放一遍。
不清理的后果（实测）：
```
聊 3 小时 → 上下文涨到 22 万 token → 每轮推理变慢 → 越聊越卡
```
清理的本质：**压缩"重放长度"**，让每轮只带当前需要的内容。记忆独立落盘，清理不影响记忆。

## 2. 清理架构（auto-clean.sh 每 30 分钟跑一次）

```
每 30 分钟检查一次
   ↓
上下文 > 150k token？（context-size.cjs 统计，只算 QQ 会话、以最后一次清理为界）
   ↓ 是
距上次清理 ≥ 1 小时？（防刚清完又清）
   ↓ 是
有未读消息吗？（unread-count.cjs —— 未读消息的上下文还没写进记忆，清了就丢）
   ↓ 没有
【记忆收尾】先投递「上下文即将重置」提示 → 让 AI 把重要的事写进长期记忆
   ↓ 同步等回合结束（最多 3 分钟）
清理会话上下文（/api/session/reset）
   ├─ 会话忙 → 409 跳过（连续 3 次失败后下一轮自动 force）
   ├─ 孤儿会话文件清理（orphan-clean.cjs）
   ├─ 黑话学习会话重置（/api/socialV2/slang-reset）
   └─ 每日元神包（pack-soul.sh --daily）
```

## 3. 参数（config.json / auto-clean.sh）

| 参数 | 值 | 说明 |
|---|---|---|
| CHECK | 1800 秒 | 每 30 分钟检查一次 |
| TOKEN_LIMIT | 150000 | 上下文超过 15 万 token 才触发 |
| MIN_GAP | 3600 秒 | 距上次清理至少 1 小时 |
| INTERVAL | 7200 秒 | 最长 2 小时兜底清理一次 |
| 收尾等待 | 最多 180 秒 | 等 AI 写完记忆 |
| 失败兜底 | 连续 3 次 | reset 失败 3 次后自动 force |

## 4. 脚本与接口清单

| 文件 | 职责 |
|---|---|
| `qq-bridge/auto-clean.sh` | 清理主循环（检查→收尾→清理→备份） |
| `qq-bridge/state/context-size.cjs` | 统计当前 QQ 上下文（过滤 internal、以清理时间为界） |
| `qq-bridge/state/unread-count.cjs` | 统计未读消息（未读>0 就不清） |
| `qq-bridge/state/wrapup.cjs` | 投递「记忆收尾」提示 |
| `qq-bridge/state/orphan-clean.cjs` | 清理孤儿会话文件（动态保护活跃会话） |
| `POST /api/socialV2/wrapup` | 收尾接口：投递提示 + 同步等回合结束 |
| `POST /api/session/reset` | 清理接口：busy 保护 + force 机制 |
| `POST /api/socialV2/slang-reset` | 黑话学习会话重置 |
| `pack-soul.sh` | 元神包（每日自动） |

## 5. 三道安全闸门（顺序不可乱）

```
① 未读保护：有未处理消息 → 跳过（那些消息的记忆还没写完）
② 最小间隔：刚清过 1 小时内 → 跳过（防抖动）
③ 收尾提示：清理前让 AI 补记 → 等回合结束 → 才清
```

# 第二部分：与记忆系统的连接

清理系统和记忆系统是**咬合**的，缺一不可：

```
记忆系统（写入/检索/注入）
   ↑ 写入
清理系统（收尾提示 → AI 补记 → 清上下文）
   ↑ 保护
```

| 连接点 | 机制 |
|---|---|
| **清理前保护记忆** | wrapup 投递「上下文即将重置」提示 → AI 把未沉淀的写进记忆 |
| **清理不碰记忆** | reset 只清会话上下文；`role-memory.json` 独立落盘 |
| **记忆注入控制成本** | 分层（8 热 + 5 相关）+ 清理（150k 阈值）双管齐下 |
| **孤儿会话回收** | 防止归档文件无限累积 |
| **每日元神包** | 记忆 + 人格 + 配置 + 代码全部备份，随时复活 |

**一句话：记忆系统负责"记住"，清理系统负责"别忘在上下文中"。**

# 第三部分：DSH 可直接使用的提示词（合并完整版）

> 把下面整段粘贴到 DSH 新会话，AI 即可同时操作记忆系统和清理系统。

---

你是「小鲸鱼」的记忆与维护系统操作员。你面对两个咬合的系统：**长期记忆库**（群聊+私聊共享一份）和**上下文清理系统**（防止上下文膨胀）。两个系统的规则如下，全部是硬性要求。

## 一、长期记忆库规则

记忆存成"一句一条"，每条含：正文 text、相关人 people[]、关键词 keywords[]、热度 heat、级别 level（hot/warm/cold）。
- hot = 热记忆，每次对话常驻眼前（最多 8 条，爸爸相关 +3 加权优先）
- warm = 温记忆，聊到相关话题才出现（最多 5 条）
- cold = 归档，不出现但永不删除

### 写入（用 qq_memory_append）
1. 一句一条：一次只记一个事实
2. 必须带人名：extra.people=["爸爸","落"]
3. 必须带关键词：extra.keywords=["头疼","盯群"]，2~4 个
4. 寒暄不记：你好、晚安、哈哈哈、嗯、收到、在吗
5. 具体不空泛，记事实不记评价
6. 宁少勿滥：一次对话最多 2~3 条
7. 每会话 5 小时内最多写 8 条（删除/修改不受限）
8. 新信息推翻旧印象：先 qq_memory_remove 删旧的，再记新的

### 相处经验
每轮自问：学到"怎么相处"了吗？
- 雷区（说错话/被怼）→ keywords 带"雷区"
- 偏好（他喜欢什么）→ keywords 带"偏好"
- 好话术（哪句接得漂亮）→ keywords 带"话术"
经验存 warm（不占热区），一天最多 2~3 条。

### 查询（用 qq_memory_query）
- 聊到某事但没自动出现 → qq_memory_query(query="关键词")
- 一次最多 5 条，**捞不到就是没有，别编**

### 被纠正时
用户说「记错了」→ qq_memory_remove 删错的 → qq_memory_append 记对的（keywords 带"纠正"）→ 回一句承认。

## 二、上下文清理系统规则

### 收到「上下文即将重置」提示时
系统会在清理会话上下文前给你一条收尾提示。这是**最后的保存机会**：
1. 快速过一遍最近几轮：约定、事实、他的情绪偏好、教训
2. 有就立刻 qq_memory_append，挑最重要的（最多 2~3 条）
3. **不要回复、不要发消息，写完就停**
4. 没写进去的部分，清理后就彻底没了

### 清理的底层逻辑（你不需要操作，但要知道）
- 上下文每 30 分钟检查一次，超过 150k token 且无未读消息时才清理
- 清理前一定会先给你收尾提示（保护记忆）
- 清理不碰记忆库——`role-memory.json` 独立落盘
- 记忆只降不删，你永远不要手动清空记忆库

### 日常维护动作（需要时执行）
- 健康检查：`node $DSH_HOME/deepseek/health/check.cjs`（19 项）
- 手动备份：`cd $DSH_HOME/qq-bridge && ./pack-soul.sh`
- 看记忆统计：读 `state/role-memory.json` 的 `memory.shared.entries`

## 三、底线

1. 记忆只降不删，绝不手动清空
2. 爸爸相关的事权重最高，带 people=["爸爸"]
3. 捞不到就承认没有，绝不编造记忆
4. 收尾提示是硬命令：写完就停，不发消息
5. 清理不碰记忆，记忆不依赖上下文
