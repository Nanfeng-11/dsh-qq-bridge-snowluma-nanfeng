## 二、文件结构

```
qq-bridge/
├── config.json              # 主配置（模型、白名单、限速、主动频率）
├── roles/
│   └── 你的角色.md      # 当前人格卡（约 10.3k 字符）
├── state/
│   ├── role-memory.json     # **共享**长期记忆（单一 memory.shared，群聊+私聊共用一份）
│   ├── initial-prompts.json # 每个会话的操作者背景提示（只首次唤醒注入）
│   ├── social-v2.json       # 各群/私聊缓存、唤醒配置
│   ├── sessions.json        # QQ会话 → DSH会话映射
│   ├── .last-clean          # 上次清理的 unix 时间戳
│   ├── auto-clean.log       # 清理日志
│   ├── guardian.log         # 巡检日志
│   ├── bridge.log           # 桥接运行日志（业务事件）
│   └── backup/              # 自动备份目录
├── bridge-run.log           # 桥接 stdout/stderr（崩溃栈、退出码）
├── run-bridge.sh            # node 托管（3 秒自动重启）
├── is_running.sh            # 进程检测（返回 0/1）
├── pidof.sh                 # 按 cmdline 打印 PID
├── startup.sh               # 幂等启动全部服务
├── auto-clean.sh            # 会话清理脚本
└── guardian.sh              # 自愈巡检脚本
```

## 三、自动任务说明

### run-bridge.sh（常驻托管）

1. `node src/bridge.js`，退出后 3 秒重启
2. 每次退出写一行 `[supervisor] 桥接退出，退出码=xxx`（137=被 SIGKILL，用于定位被杀原因）
3. 停止方式：`touch state/bridge.stop` 后杀掉托管进程

### auto-clean.sh（每 5 小时）

1. 💾 **备份** `role-memory.json` + `social-v2.json`
2. 同步记忆（social-v2 → role-memory）
3. 重置 4 个活跃会话（上下文归零）
4. 写 `state/.last-clean`；**重启服务不会立即再清一次**（旧版一重启就清，会话白建）

**备份保留**：记忆 10 份 / 状态 5 份

### guardian.sh（每 2 分钟）

1. 托管进程不在 → 启动
2. 托管在但 node 不在 → 等 6 秒复核，仍未起就重启
3. 进程在但控制台 3100 无响应（假活）→ 杀掉重启
4. 清理守护挂了 → 拉起
5. 日志轮转（>1MB 截断）、备份轮转、config.json 缺失自恢复
6. 一切正常时每 30 分钟记一次心跳，其余不刷日志

## 四、手动检查命令

```bash
cd ~/qq-bridge

# 进程状态（推荐，pidof 会跳过自身与 shell 包装）
for k in run-bridge.sh src/bridge.js guardian.sh auto-clean.sh; do
  printf "%-16s %s\n" "$k" "$(./pidof.sh "$k" | tr '\n' ' ')"
done

# 控制台健康
CT=$(cat state/console-token)
node -e 'const h=require("http");h.get("http://127.0.0.1:3100/api/status?token='"$CT"'",r=>{let d="";r.on("data",c=>d+=c);r.on("end",()=>console.log(d.slice(0,400)))})'

# 日志
tail -30 state/guardian.log
tail -30 state/auto-clean.log
tail -40 bridge-run.log        # 崩溃栈 / 退出码在这里

# 一键启动（幂等，已运行不会重复起）
./startup.sh

# 强制重启桥接
touch state/bridge.stop; for p in $(./pidof.sh 'src/bridge.js'); do kill -9 $p; done
for p in $(./pidof.sh 'run-bridge.sh'); do kill -9 $p; done
rm -f state/bridge.stop; ./startup.sh
```

## 五、常见问题与修复

| 现象 | 原因 | 修复 |
|---|---|---|
| QQ 不回消息 | 桥接进程死了 | 已由 run-bridge 3 秒自愈 + guardian 2 分钟兜底；手动 `./startup.sh` |
| guardian 报"运行中"但实际已死 | **旧版 is_running.sh 自匹配 bug**：关键字在自己的 argv 里，永远返回 0；且 `ps \| grep` 会匹配到命令自身 | 已重写：跳过自身 PID、跳过 is_running.sh/pidof.sh、跳过 `bash -c`；改为 `/proc/<pid>/cmdline` 精确匹配 |
| 进程在但控制台 3100 连不上 | 假活（端口没绑上） | guardian 现在会探活 3100，无响应就重启 |
| SnowLuma 断线 | 云服务器内存不足（4GB） | 升级到 8GB（根本解决） |
| 回复变慢 | 会话上下文太大 | auto-clean 每 5 小时清理 |
| 记忆丢失 | 备份文件损坏 | 从 `state/backup/role-memory-*.json` 恢复 |
| 一重启就清会话 | 旧 auto-clean 启动即清理 | 已加 `.last-clean` 时间戳守卫 |
| `./startup.sh` 卡住不动 | **toybox sh 死锁**：旧 is_running.sh 用 `$( )` 命令替换取 cmdline，父 shell 等管道、子 shell 等孙进程互相等待 | 已改成直接 `grep -qa` 读 `/proc/*/cmdline`，不再用命令替换（单次 0.3 秒） |
| 记忆要跨群/私聊共享 | 旧版按会话分键存（private:/group:） | 已合并为单一 `memory.shared`；加载时自动迁移旧分键并备份到 `state/backup/role-memory-premerge-*.json` |

## 六、待优化项

| 优先级 | 事项 | 状态 |
|---|---|---|
| 🔴 高 | **云服务器内存 4GB → 8GB** | 待处理（SnowLuma 断线根因） |

| 🟢 低 | 桥接凌晨偶发被 SIGKILL，原因未定位 | 已有退出码日志，下次复发可查 exit=137 前后的 `bridge.log` |
| 🟢 低 | 云端 ffmpeg 缺失导致图片压缩失败 | 不影响收发，仅按原图发送 |

## 七、关键配置速查

| 配置 | 位置 | 当前值 |
|---|---|---|
| 推理档位 | `config.json` → `dsh.reasoningEffort` | `low` |
| 白名单 | `config.json` → `allow` | 私聊 <主人QQ号> / 群 <群号·任务群>, <群号3>, <群号2> |
| 发送限速 | `config.json` → `socialV2.send` | 20条/分 |
| 主动发起 | `config.json` → `socialV2.proactive` | 开启，15~30分，50% |
| 默认唤醒（私聊） | `config.json` → `socialV2.wake.privateDefaultMode` / `privateProbability` | `active` / `1`（爸爸发什么都醒） |
| 默认唤醒（群聊） | `config.json` → `socialV2.wake.groupDefaultMode` / `groupProbability` | `diving` / `0.15`（普通消息 15%，@/名字/提问/拍一拍/关键词必醒） |
| 角色注入上限 | `config.json` → `role.maxInjectChars` | 12000 |
| 人格卡分层 | 角色卡 `〔按需〕` 标记 | 每次唤醒只注入核心 ~7.1k 字；qq_get_prompt 返回全文 11.9k |
| 记忆检索 | `config.json` → `socialV2.memory` | 热 8 条常驻 + 相关 ≤5 条（人名/关键词/语义 n-gram）；爸爸加权 +3；命中加热 |
| SnowLuma 地址 | `config.json` → `snowluma` | `<你的云服务器IP>:3000/3001` |
