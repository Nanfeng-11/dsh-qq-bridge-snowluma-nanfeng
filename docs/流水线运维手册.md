## 一、系统全景

### 1.1 三端架构

```
QQ 账号
  │ 协议
  ▼
SnowLuma（云 Windows 服务器 <你的云服务器IP>）
  ├─ OneBot HTTP :3000
  └─ OneBot WS   :3001
        │ WebSocket
        ▼
手机（Android · DSH Mobile）
  ├─ 桥接 bridge.js（控制台 :3100）
  ├─ DSH 引擎（WebUI :3080）
  ├─ MCP 三件套（snowluma / host / web-search）
  ├─ 托管 run-bridge（3 秒重启）
  ├─ 巡检 guardian（2 分钟探活）
  └─ 清理 auto-clean（动态触发）
        │ 模型 API
        ▼
DeepSeek 账号（deepseek-flash，推理档 low）
```

### 1.2 关键目录

| 路径 | 内容 |
|---|---|
| `$DSH_HOME/qq-bridge/` | 桥接主目录（代码 + 状态 + 脚本） |
| `qq-bridge/src/bridge.js` | 主程序（约 12k 行） |
| `qq-bridge/roles/你的角色.md` | 人格卡（约 10.7k 字，核心层 5.9k） |
| `qq-bridge/config.json` | 全部配置（含密钥，权限 600） |
| `qq-bridge/state/` | 运行时数据（记忆、会话、情绪、日志） |
| `qq-bridge/state/role-memory.json` | 长期记忆库（一句一条） |
| `qq-bridge/state/mood.json` | 情绪状态 |
| `qq-bridge/backups/` | 元神包（每日） |
| `$DSH_HOME/deepseek/health/check.cjs` | 健康检查脚本 |
| `/data/user/0/app.dsh.mobile/files/engine/extensions/` | 扩展（ffmpeg/ImageMagick） |

### 1.3 数据流（一条消息的生命周期）

```
QQ 消息 → SnowLuma → WS 3001 → 桥接
  → 入站处理（入库 unread、情绪分析、黑话素材）
  → 唤醒判断（@/名字/关键词/提问/概率）
  → 构建唤醒 prompt（人格卡 + 记忆 + 心情 + 语感 + 表情策略）
  → DSH 会话（deepseek-flash，low）
  → 她调用工具（发消息/表情/语音/查记忆/等静默）
  → 回复发回 QQ
  → 记忆检查（写记忆，一句一条）
```

## 二、从零部署（7 步）

### 步骤 1：手机装 DSH
```bash
# 确认引擎可用
curl -s http://127.0.0.1:3080/ -o /dev/null -w "%{http_code}\n"   # 期望 200/401
```

### 步骤 2：装 qq-bridge
```bash
# 把插件装进 $DSH_HOME/qq-bridge（或从元神包恢复）
ls $DSH_HOME/qq-bridge/src/bridge.js
# 装依赖（如有 node_modules 缺失）
cd $DSH_HOME/qq-bridge && pnpm install --offline 2>/dev/null || npm install
```

### 步骤 3：云端装 SnowLuma（Windows）
1. 云服务器（建议 2C4G 起，最好是 2C8G）装 Windows
2. 装 SnowLuma，用 QQ 小号登录
3. 开启 OneBot HTTP 3000 / WS 3001，设置 access token
4. 安全组放行 3000、3001

### 步骤 4：填配置（3 处必填）
```bash
cd $DSH_HOME/qq-bridge
node -e '
const fs=require("fs");
const c=JSON.parse(fs.readFileSync("config.json","utf8"));
c.snowluma.wsUrl="ws://<云IP>:3001";
c.snowluma.httpUrl="http://<云IP>:3000";
c.snowluma.accessToken="<OneBot token>";
c.dsh.baseUrl="http://127.0.0.1:3080";
fs.writeFileSync("config.json",JSON.stringify(c,null,2));
'
```

### 步骤 5：白名单与策略
```json
{
  "allow": {
    "private": ["<爸爸QQ号>"],
    "groups": ["<群1>", "<群2>"]
  },
  "socialV2": {
    "wake": { "groupProbability": 0.15, "privateProbability": 1 },
    "voice": { "enabled": true, "tts": { "apiKey": "<MiniMax key>" } }
  }
}
```

### 步骤 6：启动
```bash
cd $DSH_HOME/qq-bridge
bash startup.sh          # 启动 桥接+托管+巡检+清理
```

### 步骤 7：验证
```bash
cd $DSH_HOME/deepseek/health
node check.cjs           # 19 项全绿才算通
```

**成功标志**：`mode=reserved2 / dshReady=true / snowluma connected+online+good`

## 三、核心模块原理

### 3.1 记忆系统（`src/memory-entries.js` + `state/role-memory.json`）

- **一句一条**：每条 = 一个事实 + `people[]` + `keywords[]` + `heat` + `level`
- **三级**：`hot`（常驻 8 条）/ `warm`（按需）/ `cold`（归档不删）
- **降级**：3 天 → warm，30 天 → cold，只降不删
- **检索**：精确（人名/关键词）+ 语义（中文 2-gram 重叠 ≥ 0.2），最多 5 条
- **加热**：被注入 +0.2 / 被命中 +1；爸爸相关排序 +3
- **写入**：寒暄过滤；每会话 5 小时最多 8 条；被纠正时删错记对
- **参数**：`config.socialV2.memory`

### 3.2 人格卡（`roles/你的角色.md`）

- 分层注入：`〔按需〕` 标记的章节不进核心层
- 核心层约 5.9k 字（语音/性格/记忆/情绪/底线），全文 10.7k 字
- `qq_get_prompt` 返回全文
- 改人格卡不用重启（每次读文件）

### 3.3 情绪状态（`src/mood.js` + `state/mood.json`）

- 心情 0~1 + 10 标签，词表自动分析入站消息
- 单条消息变化 ≤0.12；心情半衰期 6 小时，标签 45 分钟
- 注入「此刻的心情」，只影响语气不影响判断

### 3.4 语音（`src/tts.js`）

- MiniMax T2A v2，`female-shaonv`，语速 1.1
- `tts:情绪:文本` 语法（happy/angry/sad/fearful/disgusted/surprised/neutral）
- 私聊不限量；群 1 条/分、3 条/时
- 发送用 `base64://`（云端 Windows 读不到手机路径）

### 3.5 自愈体系（四层）

| 层 | 实现 | 恢复时间 |
|---|---|---|
| 进程 | `run-bridge.sh` 托管 | 3 秒 |
| 服务 | `guardian.sh` 探活 3100 | 2 分钟 |
| 引擎 | MCP 启动钩子调 `startup.sh` | 20 秒 |
| 数据 | `auto-clean.sh` 清会话 + 每日元神包 | 5 小时/天 |

### 3.6 上下文清理（防越聊越慢）

`auto-clean.sh` 每 30 分钟检查：
- 上下文 > 150k token
- 距上次清理 ≥ 1 小时
- 无未读消息
- → 先投「收尾提示」让 AI 写记忆（等回合结束）→ 再清理

## 四、日常运维

### 4.1 健康检查（每天/出问题先跑）
```bash
cd $DSH_HOME/deepseek/health && node check.cjs
```
19 项：进程、控制台、DSH、SnowLuma、云端 OneBot、记忆、情绪、上下文、日志。

### 4.2 看状态
```bash
CT=$(cat $DSH_HOME/qq-bridge/state/console-token)
node -e "fetch('http://127.0.0.1:3100/api/status?token=$CT').then(r=>r.json()).then(j=>console.log(j.mode,j.dshReady,j.snowluma))"
```

### 4.3 重启桥接
```bash
cd $DSH_HOME/qq-bridge
touch state/bridge.stop
for p in $(bash ./pidof.sh 'src/bridge.js'); do kill $p; done
sleep 4
for p in $(bash ./pidof.sh 'src/bridge.js') $(bash ./pidof.sh 'run-bridge.sh'); do kill -9 $p; done
rm -f state.bridge.stop
bash startup.sh
```

### 4.4 备份（元神包）
```bash
cd $DSH_HOME/qq-bridge
./pack-soul.sh            # 手动
# 自动：auto-clean 每天一次，保留 5 份
```

### 4.5 改配置后要重启
`config.json` 的改动**需要重启桥接**才生效；人格卡不用。

## 五、故障手册

| 现象 | 排查 | 修复 |
|---|---|---|
| 她不说话 | `check.cjs`；看 bridge.log | 按失败项修 |
| 回消息慢 | 查上下文（第 18 项） | 等清理或手动 reset |
| 表情发不出 | 日志「找不到表情」 | `findSticker` 按名字匹配已支持 |
| 图片看不到 | 日志 ffmpeg 报错 | 用 `bin/ffmpeg` 包装器（LD_LIBRARY_PATH） |
| 云端断线 | snowluma.connected=false | 检查云服务器/SnowLuma 进程 |
| 语音发不出 | `qq_send_voice` 报错 | 检查 MiniMax key/额度 |
| 引擎重启后全挂 | 无进程 | `startup.sh`；确认 MCP 启动钩子 |
| 记忆写入被拒 | 429 节流 | 等 5 小时窗口或删改 |

## 六、交接清单

### 必须知道的
1. **config.json 含明文密钥**（MiniMax/OneBot/console），权限 600，别外传
2. **元神包**（`backups/soul-*.tar.gz`）是整套系统的复活凭据
3. **人格卡第 7 节**是记忆规则，改它会影响记忆行为
4. **白名单**（`allow.groups/private`）决定能对谁说话
5. 云端 SnowLuma 是单点，挂了要人工

### 千万别做的
- ❌ 把 `config.json` / 元神包发公开
- ❌ 在群里把唤醒概率调到 100%（烧钱）
- ❌ 删 `state/role-memory.json`（记忆就没了）
- ❌ 用 `pkill -f bridge`（会误杀自己的 shell）

### 常用数字
```
爸爸 QQ：<主人QQ号>
群：<群号·任务群>（凤台/任务群）、<群号2>（碎月）、<群号3>（土豆）、<群号4>（小群）
云端：<你的云服务器IP>:3000 / 3001
控制台：127.0.0.1:3100（token 在 state/console-token）
```

## 七、优化流水线（每次改动的标准动作）

```
1. 备份：cp 目标文件 目标.bak-$(date +%s)
2. 改：用 write/edit 工具改文件（不要在 bash 里拼引号）
3. 校验：node --check src/xxx.js（或 sh -n xxx.sh）
4. 重启：bash startup.sh（配置类）/ 单独重启 auto-clean
5. 验证：node $DSH_HOME/deepseek/health/check.cjs
6. 记录：改了什么、为什么、怎么验证
```

**写补丁脚本用 write 写文件再 node 执行**——在 bash 单引号里拼带引号的 JS 是这套环境最常见的翻车点。
